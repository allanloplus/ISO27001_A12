## 03｜觀念暖身｜事件 Event ≠ 事故 Incident

**畫面重點**

- 資訊安全事件 Event
- 可能與資訊安全有關的狀況，值得被注意、被記錄。
- 防毒軟體告警
- 帳號連續登入失敗
- 收到可疑郵件
- 很多
- 5.25／評鑑・決策
- 少數
- 資訊安全事故 Incident
- 經評鑑後，很可能危害營運或威脅資訊安全的事件。
- 勒索軟體加密檔案
- 個人資料外洩
- 官網遭置換

**對白**

- **阿拉蕾**：老師，「事件」跟「事故」聽起來好像，到底差在哪裡？
- **Allan 老師**：「事件」是發生了可能跟資安有關的狀況，例如防毒告警、帳號連續登入失敗、收到可疑郵件。
- **Allan 老師**：「事故」是經過評鑑後，確認很可能危害營運或資訊安全的事件，像勒索軟體加密、個資外洩、官網被置換。
- **Allan 老師**：所以事件很多、事故比較少，中間的過濾器，就是 5.25 的評鑑及決策。
- **阿拉蕾**：就像打噴嚏是事件，確診流感才是事故！
- **Allan 老師**：嗯，這個比喻，老師給你八十分。

## 04｜① ISMS 作業重點｜5.24 事故管理規劃及準備

**畫面重點**

- 事故管理程序通報 → 評鑑 → 回應 → 蒐證 → 學習，全流程寫清楚
- 角色與責任事故處理小組（IRT）、對外窗口、夜間假日值班與代理人
- 事故分級標準依 C／I／A、個資、營運中斷、商譽影響定義等級
- 對外通報主管機關、客戶、個資當事人、執法機關：時限與窗口先定好
- 能力與資源聯絡清單、值班表、演練、外部事故應變廠商（先簽約）

**對白**

- **Allan 老師**：進入第一部分：ISMS 作業重點。先從 5.24 規劃及準備開始。
- **Allan 老師**：第一，要有事故管理程序，把通報、評鑑、回應、蒐證、學習這整條流程寫清楚。
- **Allan 老師**：第二，角色與責任。誰是事故處理小組？誰是對外窗口？晚上和假日找誰？代理人又是誰？
- **Allan 老師**：第三，分級標準。依照對機密性、完整性、可用性，還有個資、營運和商譽的影響，定義事故等級。
- **Allan 老師**：第四，對外通報。主管機關、客戶、個資當事人，各自的時限和窗口，要事先定好。
- **Allan 老師**：第五，能力和資源。聯絡清單、值班表、演練，還有外部的事故應變廠商，最好平時就把合約簽好。
- **阿拉蕾**：哇！出事的時候才找廠商，會不會來不及？
- **Allan 老師**：一定來不及！真的出事那一刻，好的應變團隊都在忙，臨時報價、跑採購流程，黃金時間早就過了。

## 05｜① ISMS 作業重點｜偵測的基礎：存錄・監視・鐘訊同步

**畫面重點**

- 8.15
- 存錄 Logging
- 使用者活動、例外、錯誤、安全事件
- 特權帳號操作要記
- 防竄改、集中保存
- 定義保存期限
- 8.16
- 監視活動 Monitoring
- 先建立「正常」基準線
- 網路、系統、應用異常偵測
- 告警門檻與處理責任
- SIEM／SOC／MDR
- 8.17
- 鐘訊同步 Clock sync
- 對時到核准的時間源（NTP）
- 時區一致（UTC+8？UTC？）
- 地端、雲端、網通設備都要

**對白**

- **Allan 老師**：8.15 存錄：要記錄使用者活動、例外、錯誤和安全事件。日誌要防竄改，也要定義保存期限，特權帳號的操作更要記。
- **阿拉蕾**：如果管理員自己可以刪日誌，那不就是小偷自己管監視器？
- **Allan 老師**：完全正確！所以日誌最好即時集中送到另一台主機，而且管理權限要分開。
- **Allan 老師**：8.16 監視活動：先建立正常行為的基準線，才知道什麼叫異常。告警要有門檻，也要有人負責看、負責處理。
- **Allan 老師**：8.17 鐘訊同步：所有系統都要對時到核准的時間來源，例如內部的 NTP 伺服器，時區也要一致。
- **阿拉蕾**：這樣比對日誌的時候，時間軸才排得起來！

## 06｜① ISMS 作業重點｜6.8 事件通報 ＋ 5.25 評鑑及決策

**畫面重點**

- 6.8 通報管道
- 服務台分機
- 資安信箱
- 線上表單
- 主管
- 看到就說，不要自己處理
- 不要求、也不鼓勵員工自行測試可疑弱點，以免破壞證據或觸法。
- 5.25 分級與決策（範例）
- 等級情境決策
- 低
- 釣魚信，無人點擊
- 服務台記錄結案
- 中
- 單機中毒，已隔離
- 資訊部處理＋登錄
- 高
- 多台加密／個資外洩
- 啟動 IRT、通報高層、對外通報
- 評鑑結果與「決策理由」要留下紀錄。

**對白**

- **Allan 老師**：6.8 資訊安全事件通報：要提供簡單、而且大家都知道的通報管道，像服務台、資安信箱、線上表單。
- **Allan 老師**：重點是「看到就說」。而且不要讓員工自己去測試可疑的弱點，不然好心反而會破壞證據，甚至觸法。
- **阿拉蕾**：原來不能自己當柯南！
- **Allan 老師**：收到通報後，就進入 5.25 評鑑及決策：依分級標準，判斷這是不是事故、是哪一級。
- **Allan 老師**：例如釣魚信沒人點，服務台記錄結案；單機中毒已隔離，資訊部處理；多台主機被加密或個資外洩，就要啟動事故處理小組，往上通報、對外通報。
- **Allan 老師**：評鑑的結果，還有決策的理由，都要留下紀錄。這是稽核員一定會看的地方。

## 07｜① ISMS 作業重點｜5.26 事故回應 ＋ 5.28 證據蒐集

**畫面重點**

- 圍堵隔離主機、停用帳號
- 根除清除後門與惡意程式
- 復原乾淨備份還原、驗證後上線
- 溝通高層、員工、客戶、主管機關
- 5.28 證據蒐集
- 識別
- 蒐集
- 取得
- 保存
- 監管鏈 Chain of custody：誰、何時、取得什麼、如何保管
- 先取證、再處置：記憶體與磁碟映像、日誌匯出、雜湊值
- 考量法律上的可採性，必要時委請鑑識專業

**對白**

- **Allan 老師**：5.26 事故回應，一般有四個動作：圍堵、根除、復原，還有貫穿全程的溝通。
- **Allan 老師**：圍堵是先止血，例如隔離中毒主機、停用被盜帳號；根除是清掉後門和惡意程式；復原是從乾淨的備份還原，確認正常再上線。
- **Allan 老師**：5.28 證據蒐集：要能識別、蒐集、取得及保存證據，並且保留監管鏈，也就是誰、在什麼時間、拿了什麼證據、怎麼保管。
- **阿拉蕾**：那中毒的電腦，可以直接重灌嗎？這樣比較快耶！
- **Allan 老師**：千萬不要！先做記憶體和硬碟映像、保留日誌，再處置。一重灌，攻擊路徑就查不到了，要提告也沒有證據。

## 08｜① ISMS 作業重點｜5.27 由資訊安全事故中學習

**畫面重點**

- 根因分析5 Whys、魚骨圖／不要只寫「人為疏失」
- 矯正措施連結條文 10.2／追蹤有效性
- 更新風險風險評鑑、控制措施／適用性聲明
- 訓練與演練把真實案例／變成教材
- 管理審查事故趨勢／納入 9.3 輸入
- 同樣的事故／不發生第二次

**對白**

- **Allan 老師**：最後是 5.27 從事故中學習。事故結案前要做根因分析，找出真正的原因，而不是只寫一句「人為疏失」。
- **Allan 老師**：然後連結到條文 10.2 的矯正措施，必要時更新風險評鑑和控制措施。
- **Allan 老師**：再把經驗回饋到教育訓練和演練，並且把事故趨勢放進管理審查。
- **阿拉蕾**：所以事故不是丟臉的事，是免費的教材！
- **Allan 老師**：不是免費喔，通常是很貴的學費。所以更要學到東西。

## 09｜管理實務案例｜案例：中型製造業的勒索軟體週末

**畫面重點**

- 週五 21:40EDR 告警「可疑 PowerShell」，只寄到上班信箱，無人值班
- 8.16
- 週六 02:15攻擊者以未啟用 MFA 的 VPN 帳號登入，內網橫向移動
- 5.25
- 週一 08:30生產排程系統、檔案伺服器全部被加密
- 5.26
- 週一 09:10IT 主管為求快，直接重灌兩台主機，證據消失
- 5.28
- 週一 14:00才通知總經理；客戶交期延誤，無人對外溝通
- 6.8
- 改善後
- 告警分級＋委外 MDR 24h 值班
- VPN 強制 MFA
- 離線／不可變備份
- 事故應變手冊＋年度演練
- 先蒐證、再處置

**對白**

- **Allan 老師**：來看一個實際的管理案例，這是綜合多家企業的情境改編的。一家中型製造業，遇到勒索軟體。
- **Allan 老師**：週五晚上九點四十分，EDR 跳出可疑 PowerShell 的告警，但告警只寄到上班信箱，沒有人值班。
- **Allan 老師**：半夜兩點，攻擊者用一個沒有多因子驗證的 VPN 帳號，在內網橫向移動。
- **Allan 老師**：週一早上，生產排程系統和檔案伺服器，全部被加密。
- **Allan 老師**：更慘的是，IT 主管為了趕快恢復，直接重灌兩台主機，證據全部消失。
- **阿拉蕾**：啊！那就不知道駭客是從哪裡進來的了！
- **Allan 老師**：而且下午兩點才通知總經理，客戶交期延誤，也沒有人出面溝通。
- **Allan 老師**：對應控制措施：8.16 告警沒人處理、6.8 和 5.25 通報分級失靈、5.28 蒐證被破壞、5.26 回應缺乏溝通。
- **Allan 老師**：改善後，他們導入告警分級和委外 MDR 值班、VPN 強制多因子驗證、離線備份、事故應變手冊和年度演練，並且規定先蒐證、再處置。

## 10｜② 稽核查核重點｜三管齊下：文件・訪談・紀錄

**畫面重點**

- 文件面
- 事故管理程序是否涵蓋全流程
- 分級標準、通報時限是否明確
- 聯絡清單是否為最新版本
- 稽核小技巧：現場撥一通窗口電話
- 訪談面
- 隨機問同仁：「收到可疑郵件怎麼辦？」
- 問 IRT 成員：「你的角色是什麼？」
- 答案與程序一致才算落實
- 紀錄面
- 事件／事故登錄表
- 演練紀錄與檢討報告
- 矯正措施追蹤
- 「全年零事件」→ 要追問！

**對白**

- **Allan 老師**：第二部分，稽核查核重點。現在換我戴上稽核員的帽子。
- **阿拉蕾**：我也要戴！嗶嗶！稽核員阿拉蕾上線！
- **Allan 老師**：文件面：看事故管理程序、分級標準、通報時限，還有聯絡清單是不是最新的。我常常現場打一通電話，測試窗口通不通。
- **Allan 老師**：訪談面：隨機找一位同仁問：「收到可疑郵件，你會怎麼做？」答案跟程序一致，才代表真的有落實。
- **Allan 老師**：紀錄面：調閱事件和事故登錄表、演練紀錄、檢討報告，還有矯正措施的追蹤。
- **Allan 老師**：如果受稽單位說：「我們這一年零事件」，我反而會追問：是真的沒有，還是沒發現、沒記錄？
- **阿拉蕾**：零事件不是好事喔？
- **Allan 老師**：有防毒、有防火牆，一整年連一筆攔截紀錄都沒有，通常代表事件沒有被記錄，而不是沒有發生。

## 11｜② 稽核查核重點｜追蹤法：抽一筆事件單，一條線拉到底

**畫面重點**

- 抽樣／事件單
- ◀ 往前追
- 8.15/8.16原始告警與日誌
- 8.17各系統時間戳一致？
- 往後追 ▶
- 6.8何時通報
- 5.25分級與理由
- 5.26處置紀錄
- 5.28證據保存
- 5.27/10.2根因・矯正
- 技術抽查
- NTP 設定畫面
- 日誌保存期限與存取權限
- SIEM 告警處理率
- 管理者帳號操作日誌

**對白**

- **Allan 老師**：我最推薦的稽核手法，叫做「追蹤法」。從事件登錄表抽一筆，一路往前追、往後追。
- **Allan 老師**：往前追原始的告警跟日誌，看 8.15、8.16 有沒有真的在運作；再對照各系統的時間戳記，驗證 8.17 鐘訊同步。
- **Allan 老師**：往後追：什麼時候通報、怎麼分級、理由是什麼、做了哪些處置、證據怎麼保存，最後有沒有根因分析和矯正措施。
- **Allan 老師**：技術面也要抽查：NTP 設定、日誌的保存期限跟存取權限、SIEM 告警的處理率，以及管理者帳號的操作日誌。
